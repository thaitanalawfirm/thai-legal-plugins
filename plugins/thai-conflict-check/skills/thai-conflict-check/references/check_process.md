# check_process.md — กระบวนการตรวจและระบบฐานข้อมูล conflict

อ่านไฟล์นี้เมื่อต้องดำเนินการตรวจจริง หรือวางระบบฐานข้อมูลให้สำนักงาน

---

## สารบัญ
1. รายชื่อที่ต้องนำมาตรวจ
2. ฐานข้อมูลที่ต้องเทียบ
3. ขั้นตอนการค้นเทียบ
4. การวางระบบฐานข้อมูล conflict ของสำนักงาน

---

## 1. รายชื่อที่ต้องนำมาตรวจ

รวบรวมจากบันทึกรับเรื่อง (`thai-client-intake`) ให้ครบ:
- **ลูกความใหม่** — ชื่อบุคคล/นิติบุคคล และผู้มีอำนาจสั่งงาน
- **คู่กรณี** — ฝ่ายตรงข้ามทั้งหมด
- **ผู้เกี่ยวข้อง** — พยานสำคัญ ผู้ค้ำประกัน ผู้ร่วมรับผิด บุคคลที่สาม
- **นิติบุคคลที่เชื่อมโยง** — บริษัทในเครือ บริษัทแม่-ลูก กรรมการ/ผู้ถือหุ้นรายใหญ่ที่
  เกี่ยวข้องกับเรื่อง
- **ชื่ออื่นที่เกี่ยวข้อง** — ชื่อเดิม ชื่อทางการค้า

ยิ่งรายชื่อครบ การตรวจยิ่งแม่น — ชื่อที่ตกหล่นคือช่องที่ conflict หลุดรอด

## 2. ฐานข้อมูลที่ต้องเทียบ

เทียบรายชื่อข้างต้นกับ:
- **ลูกความปัจจุบัน** ทั้งหมดของสำนักงาน
- **ลูกความเดิม** (เรื่องที่ปิดแล้ว) — เพราะหน้าที่รักษาความลับยังอยู่
- **คู่กรณีในเรื่องที่สำนักงานเคย/กำลังทำ** — เผื่อลูกความใหม่เคยเป็นคู่กรณีของลูกความเรา
- **ผู้มาปรึกษาที่เคยเข้ามา** (แม้ไม่ได้รับเป็นลูกความ) — เพราะอาจได้ข้อมูลความลับมาแล้ว
- **ผลประโยชน์ของทนาย/สำนักงาน** — รายการส่วนได้เสียที่ประกาศไว้

## 3. ขั้นตอนการค้นเทียบ

1. ค้นแต่ละชื่อในฐานข้อมูลทั้งหมดข้างต้น
2. ค้นด้วยชื่อหลายรูปแบบ (ชื่อเต็ม ชื่อย่อ ชื่อทางการค้า ชื่อภาษาอังกฤษ) เพื่อกันการพลาด
3. เมื่อพบรายชื่อตรงหรือใกล้เคียง ดึงเรื่องที่เกี่ยวข้องมาพิจารณาความเกี่ยวพัน
4. บันทึกทุกการพบ (hit) เพื่อนำไปวิเคราะห์ประเภทและระดับ (`conflict_types.md`)
5. หากไม่พบ ก็บันทึกว่าตรวจแล้วไม่พบ (เพื่อเป็นหลักฐานว่าได้ตรวจ)

> **หากสำนักงานยังไม่มีฐานข้อมูลให้เทียบ** สกิลตรวจ conflict ให้ครบไม่ได้ — ต้องระบุชัดว่า
> "ตรวจกับข้อมูลที่ผู้ใช้ให้เท่านั้น ต้องเทียบกับฐานข้อมูลลูกความจริงของสำนักงานก่อนสรุป"

## 4. การวางระบบฐานข้อมูล conflict ของสำนักงาน

ระบบที่ดีควรเก็บอย่างน้อย:
```
| เรื่องที่ | ลูกความ | คู่กรณี | ผู้เกี่ยวข้อง | ทนายผู้รับผิดชอบ | สถานะ | วันที่เปิด/ปิด |
```
หลักการ:
- บันทึกทุกเรื่องที่รับ **และทุกผู้มาปรึกษา** (เพื่อจับประเด็นข้อมูลความลับ)
- อัปเดตทันทีเมื่อรับเรื่องใหม่ และค้นได้ด้วยชื่อทุกฝ่าย
- เก็บบันทึกผลการตรวจ conflict ของทุกเรื่อง
- จำกัดการเข้าถึงข้อมูลความลับตามความจำเป็น (สอดคล้อง PDPA และความลับลูกความ)

> ระบบนี้ทำงานคู่กับ `thai-matter-management` ที่บริหารสำนวน — ใช้ฐานข้อมูลเดียวกันได้
